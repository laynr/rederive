rederive.json

spec v1 — how a repo earns an A

An A grade means: the rederive page downloaded your pinned inputs, verified their hashes, re-ran your transform inside a no-network browser sandbox, and the output matched your committed data byte-for-byte. Trust me becomes check me.

To opt in, commit a rederive.json at the repository root:

{
  "rederive": 1,
  "inputs": [
    {
      "name": "upstream",
      "repo": "OWNER/REPO",
      "commit": "31986353ea2012c8a84ac7fc01f244aefb6a522d",
      "path": "data.json",
      "sha256": "3a42d964db75aba91a52a37483e0419f3f325a7c9cb03c353b4ef76cfb793b35"
    },
    { "name": "raw", "path": "sources/raw.csv" }
  ],
  "transform": { "module": "scripts/transform.mjs", "entry": "derive" },
  "outputs": [ "data/report.json" ]
}

inputs

Two kinds:

  • External pin — repo + a 40-hex commit + path, and at least one content hash (sha256 of the raw bytes, and/or the git blobSha). The page downloads the file at exactly that commit and recomputes both hashes. A mismatch fails the run.
  • Local input — just a path committed in your own repo. The analyzed commit itself is the pin; the page checks the fetched bytes against your tree's blob sha. No hash fields needed.

transform

module is a path to a pure ES module in your repo. Relative imports to other committed modules are allowed (up to 10 files); bare or absolute specifiers are rejected. It runs in a disposable Web Worker inside a sandboxed, opaque-origin iframe whose CSP is default-src 'none', and is hard-terminated on timeout. This is layered isolation designed to deny network, storage and cookies — correctness is anchored by the byte comparison, not by trusting the transform.

Determinism rules. The same input bytes must always produce the same output bytes:

  • No wall clock. Derive any timestamp from the input content (e.g. the newest upstream date), never from Date.now().
  • No randomness, no locale-dependent formatting, no object-key ordering you don't control (build objects in a fixed order, or sort keys).
  • Byte-exact serialization: pick one and stick to it (indentation, trailing newline, number formatting).

outputs

Repo paths of the committed files your transform regenerates. The page compares the git blob sha of what your transform just produced against what is committed at the analyzed commit. Expected hashes live nowhere in the manifest — your own commit is the ground truth.

regenerating

When upstream moves: update each input's commit and sha256, re-run your transform (the same module runs in Node — crypto.subtle, TextDecoder and pure JS work in both), commit inputs + outputs together. Every commit of your repo is then independently re-derivable.

Reference implementation of this pattern: laynr/FedRAMP — resolves upstream branches to immutable commits, records blob sha + sha256 + byte count per source, shares its pure transforms between Node and the browser, and derives its generated timestamp from upstream data.

the grades

Fdata files present; no generation code, or the output is hand-edited
Ca script exists, but it fetches live, unpinned sources
Binputs pinned to commits/hashes (or committed in-tree) — the page re-downloads them and verifies the recorded hashes
Arederive.json present — the page re-runs the recipe in a sandbox and the output matches byte-for-byte
